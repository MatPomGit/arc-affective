## Uniform milestone definitions and evidence gates

| Milestone | Required evidence | Reject / block when |
|---|---|---|
| M0: Novelty and lawful source access | Current literature matrix with cited novelty gap; checked device/dataset rights, fallback and claim scope | No verifiable data access or no distinct research gap |
| M1: Frozen hypothesis/analysis protocol | Signed-off preregistration of primary endpoint, control, fixed splits/analysis, participant cap, exclusion rules | Hypothesis, split or endpoint to be changed after looking at held-out data |
| M2: Provenance, ingestion, measured quality | Runnable code, data provenance/hash, validated timestamps, QA counters, permitted local collection, deterministic tests | Unknown sensor rights, synchronization or raw biometric leakage |
| M3: Reproducible reference baselines | Strong baseline on identical protocol; honest grouped uncertainty, compute/resources, fixed seeds | Window/participant leakage, missing comparator or baseline not actually executed |
| M4: New algorithm / system contribution | Original implementation with tests, documented differential claim and proper fail-safe/fallback | Method duplicates existing work or bypasses safety/privacy boundaries |
| M5: Ablations, stress tests, uncertainty | Primary held-out experiment, ablation, negative controls, effect size/CI and failure analysis | Unsupported robustness, inappropriately independent windows or safety violation |
| M6: Manuscript and external reproduction | IEEE-style manuscript, reproducible scripts + manifest, units in figures, references, author/legal/journal audit | Incomplete evidence, unsupported generalization or unlicensed data release |

**Go/no-go logic:** M0 checks access & scientific differentiation, M1 freezes the protocol, M2+M3 establish data and comparator validity, M4 implements novel method, M5 determines if the observed data warrant the claim, and M6 packages a reviewed manuscript. **M6 completion is not a journal submission or acceptance.** Actual submission/date/identifier is recorded only when it happens.

## Work waves and dependency strategy

- **Wave A (start now):** P08, P01, P04. These can begin with synthetic replay/public-data licence checks; no raw Muse data and no Tobii gaze recording required.
- **Wave B (after source rights / baseline):** P02 when a genuinely synchronized licensed corpus exists; P05 when Leap revision/SDK and N-of-1 ethics gate are verified.
- **Wave C (after validated local streams / ethics):** P03, P06, P07. They do **not** require earlier manuscripts to be published; only the required event adapters and validated methods.
- **Stop criteria:** P02 stops at M0 without paired accessible data; P05 stops at M0 without a usable Leap interface; P03/P06 prospective trials stop until privacy/ethics clearance; P07 safety constraints prevent physical robot tests by default.

## Maintenance and closure

- The Pxx epic's M0–M6 checkboxes are **manually** checked after the corresponding issue passes its evidence gate. Linked GitHub references do not automatically synchronize checkboxes.
- Every issue/PR states exact changed files, test commands, protocol and data versions, result evidence (or explicit BLOCKED), and one responsible owner.
- Re-evaluate literature and target venue at M0 and M6. No hard deadlines are fabricated; the schedule is conditional and relative to a work start T0.
- Duplicate issues #34–#37 were closed in favor of canonical M2 #30–#33 for P01–P04; do not reopen them as new work.
